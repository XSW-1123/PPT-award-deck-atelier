# 内容获奖概率审核与遣词造句

> 视觉决定第一印象，内容决定能不能拿高分。**先审内容，再做视觉**。
> 赛事规则（分值、字数、图表数、文件格式）会随届次变化，使用前必须复核当届官方文件；
> 本文的方法论与结构不依赖具体届次。

## 1. 评委实际看什么

竞赛类展示不是「优秀事迹材料」，而是证明一条清晰的成长链：

```
目标怎么来 → 岗位要什么 → 我缺什么 → 做了什么 → 成果能否验证
        → 实践暴露了什么 → 下一步怎么改
```

常见评分三段（示例结构，非固定值）：

| 维度 | 占比（示例） | 该写什么 |
|---|---|---|
| 职业目标 | 25 | 目标如何由行业需要 + 自我认知推出；回应经济社会发展 / 数字经济等时代背景，落到具体系统，不喊口号 |
| 学习实践行动 | 50 | 时间节点 + 具体行动 + 量化成果 + 第三方可验证材料 |
| 优化改进 | 25 | 「我原本以为 → 实践中发现 → 我重新认识 → 改了什么 → 暴露什么新差距」 |

**篇幅按分值分配**：50 分的行动段应占全文近一半，不要把它写成简历罗列。

## 2. 逐条审核表

对每页 / 每段打勾，任一「否」就删或改：

| 检查项 | 通过标准 |
|---|---|
| 能否提高获奖概率 | 直接支撑某个评分维度；否则删 |
| 能否现场核验 | 有成绩单 / 公示 / 项目仓库 / 日志 / 截图 / 第三方记录；否则删 |
| 是否与目标岗位相关 | 与目标职业直接相关；无关奖项、志愿合影、征文获奖一律删 |
| 数字来源 | 能说清怎么算出来的；「欠挖 78/138/180」「+12‰」这类装饰性伪数据一律删 |
| 是否自曝评分点 | 页面上不写「对应评分项 XX 分」「本页得分」；改为内容短句 |
| 是否口号 | 删「受益匪浅 / 努力提升 / 继续奋斗 / 行稳致远」式空话 |
| 是否有时间节点 | 行动必须有「什么时候、做了什么」 |
| 是否有第三方验证 | 优先「可查」而非「自评」 |
| 是否有过渡句 | 板块之间有一句承上启下，不要硬跳 |
| 字数 / 图表 / 文件大小 | 用脚本 `assert` 自检，不靠估算 |

## 3. 删改清单（真实案例）

| 删掉 | 原因 |
|---|---|
| 主题摄影征集二等奖、征文三等奖、反诈一等奖 | 与目标岗位无关，堆奖项反而稀释主线 |
| 奖学金 / 三好学生 / 优秀团员罗列 | 与「能不能上手做事」无关，且占字数 |
| 无法解释来源的量化数据 | 评委追问会露馅 |
| 未核实的校训、办学口号 | 事实风险 |
| 「不限行业」式自我辩护 | 显得目标不清晰 |
| 答辩问答附录、课程逐门解释 | 超出字数上限，稀释主线 |
| 性格测评结论 | 若没做过就别写；第一人称真实叙述更有说服力 |

**替换示例**：
- 「我受益匪浅，综合能力得到很大提升」→「第一次接口超时，我以为是并发不够，加了线程池没用；后来定位到连接池没释放，改成 try-with-resources，压测 QPS 从 X 回到 Y」；
- 「努力提升专业能力」→「把五门专业课的课后习题重做一遍，学期末 X 门 90 以上，成绩单可查」；
- 「未来继续奋斗」→「下学期只调路径不调目标：先补分布式事务，用 XX 项目做验收」。

## 4. 遣词造句原则

1. **具体事实替代形容词**：写「改了什么、结果多少、在哪查」，不写「显著 / 大幅 / 扎实」。
2. **结论写成可核验判断**：「这条证据只说明学得会，不说明能上手，所以我只把它当地基」。
3. **用「发现真实问题 → 定位原因 → 替代方案 → 可验证结果」替代成长感悟**。
4. **第一人称、允许写错**：「我曾经想错过、后来改过来」比完美人设更打动评委。
5. **每个数字都能现场复算**：证据链页应直接说明每个数字来自哪里、怎么算。
6. **中文引号统一「」**，不留英文装饰行、不留模板占位符。
7. 每页文字控制在上限内（示例：每页 < 300 字），大字号承载结论，细节放报告。

## 5. 配套报告的合规自检

若同时提交文字报告，在生成脚本里内置：

```python
def word_count(text):
    cn = len(re.findall(r'[\u4e00-\u9fff]', text))
    en = len(re.findall(r'[A-Za-z0-9]+', text))
    return cn + en          # Word 式字数口径

assert word_count(body) <= WORD_LIMIT
assert chart_count <= CHART_LIMIT
assert os.path.getsize(pdf) <= SIZE_LIMIT
```

导出时把官方上限写成常量，脚本输出实测值（中文字符 / 西文词与数字 / Word 式字数 / 图表数 / 全字符），
确认 `OK 符合材料要求` 后才覆盖正式文件。

## 6. 内容页主件与信息的对应

| 内容段 | 适配主件 |
|---|---|
| 自我认知 | 巨数证据 + 刻度尺 + 一条「这条证据不说明什么」的自省结论 |
| 岗位认知 | 四列职责卡 + 状态条（独立做过 / 跟着做过 / 没碰过） |
| 人岗匹配 | 左右对照条或三行缺口对比，明确「还差什么」 |
| 学业基础 | 大数字 + 分科柱，底部一句「分数只说明入门，不说明能不能交付」 |
| 项目实践 | 时间 ribbon + 节点卡，每个节点带时间 + 产出 + 可查位置 |
| 能力证据 | 「证据链：每个数字都能现场复算」——列来源而非自评雷达 |
| 复盘改进 | 左右对照（原判断 vs 实践结论）+ 改了什么 |
| 后续规划 | 主干阶梯 + 分支风险路线，写「只调路径不调目标」 |
